# Login Restrictions & Role Enforcement

## Overview

The login system now enforces strict role-based login restrictions. Users can only login with the role they were assigned.

---

## Login Rules

### 🔐 Hardcoded Roles (Restricted to Specific Credentials)

These roles have fixed credentials and can ONLY be accessed with the correct email/password combination:

#### **Admin**
- Email: `admin@campus.edu`
- Password: `password`
- Must select "Admin" role to login
- ✅ Can login as Admin
- ❌ Cannot login as Student or Teacher

#### **Finance**
- Email: `finance@campus.edu`
- Password: `password`
- Must select "Finance" role to login
- ✅ Can login as Finance
- ❌ Cannot login as Student or Teacher

#### **Hostel**
- Email: `hostel@campus.edu`
- Password: `password`
- Must select "Hostel" role to login
- ✅ Can login as Hostel
- ❌ Cannot login as Student or Teacher

---

### 👥 Dynamic Roles (Role-Specific Login)

These roles are created by admin and have strict role enforcement:

#### **Student**
- Credentials generated by admin after application approval
- ✅ Can ONLY login as "Student" role
- ❌ Cannot login as Teacher, Admin, Finance, or Hostel
- If student tries to login with "Teacher" role → Error: "This account can only login as student"

#### **Teacher**
- Credentials generated by admin after application approval
- ✅ Can ONLY login as "Teacher" role
- ❌ Cannot login as Student, Admin, Finance, or Hostel
- If teacher tries to login with "Student" role → Error: "This account can only login as teacher"

---

## Login Flow

```
User enters email & password
↓
User selects role from dropdown
↓
System checks if role matches account type:
  
  IF Hardcoded Role (Admin, Finance, Hostel):
    → Verify email & password match hardcoded credentials
    → Verify selected role matches
    → Allow login
  
  IF Dynamic Role (Student, Teacher):
    → Find account in generated credentials
    → Verify email & password match
    → Verify selected role matches account's assigned role
    → If role mismatch → Show error
    → Allow login only if role matches

↓
On success: Store role & email in localStorage
↓
Redirect to dashboard
```

## Error Messages

### Hardcoded Role Errors
```
❌ "Invalid email or password for this role."
   → User selected Admin/Finance/Hostel but entered wrong credentials
```

### Dynamic Role Errors
```
❌ "This account can only login as student. Please select the correct role."
   → Student tried to login as Teacher
   → Student tried to login as Admin
   → etc.

❌ "Invalid email or password."
   → Email/password combination not found in system
```

## Implementation Details

**File:** `src/components/auth/login-form.tsx`

**Key Logic:**
```typescript
// Hardcoded roles must match selected role
if (hardcodedRoles.includes(selectedRole)) {
  const user = userProfiles[selectedRole];
  if (user.email === email && password === "password") {
    // Allow login
  }
}

// Dynamic roles must match both credentials AND selected role
else {
  const foundUser = storedCredentials.find(cred => 
    cred.email === email && cred.password === password
  );
  
  if (foundUser && foundUser.role === selectedRole) {
    // Allow login
  } else if (foundUser && foundUser.role !== selectedRole) {
    // Show: "This account can only login as {foundUser.role}"
  }
}
```

## Security Benefits

✅ **Role Enforcement** - Users cannot impersonate other roles
✅ **Account Isolation** - Each account is tied to one role
✅ **Credential Protection** - Hardcoded roles are protected
✅ **Clear Error Messages** - Users know why login failed
✅ **Prevents Privilege Escalation** - Cannot login as higher role
